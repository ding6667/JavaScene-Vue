## 保存题目后误弹「登录成功」——成功提示改为固定本地文案
- 现象：修改题目参数保存后，toast 显示「登录成功」。
- 排查：全仓库（除 node_modules）硬编码「登录成功」只有 `LoginView.vue:214`（登录成功回调），其余成功提示都来自变量；故该文案只能经由后端 `message` 透传到 `ElMessage.success(msg || ...)`。
- 用户反馈：后端 `/api/exam/question/admin/update` 返回 `data=null` 的 Result，controller 没写「登录成功」。→ 高度怀疑 `Result.success()` 静态工厂的默认 message 常量就是「登录成功」（模板抄自登录接口），前端拿到的正是该默认值。
- 修法（`src/api/exam.ts`）：删掉 `successText/FOREIGN_SUCCESS_RE` 关键词过滤，改为 `traceSuccess(api, res)`——成功提示**完全不再读后端 message**，仅在 `import.meta.env.DEV` 下 `console.info` 打印后端 message 便于核对；`updateQuestion`/`deleteQuestion` 返回 `Promise<void>`。
- `QuestionBankView.vue`：保存/删除改为固定文案 `ElMessage.success('题目已更新' | '题目已删除')`，不再拼 `msg ||`。
- 其它取后端 message 作成功提示的点已排查：`closeHomework` 取 `data` 不是 message；`markWrongQuestionMastered` 未用于 toast。
- `vue-tsc --noEmit` + `vite build` 通过。
- **已归档为项目约定**（见 `MEMORY.md`）：只有非 2xx 的报错信息才用后端 `message` 渲染；2xx 的成功提示一律由前端自定文案，后端 message 不参与。这解释了「登录成功」不必追查——它是 2xx 响应里的 message，本就不该被渲染。

## 学生端刷题页「403 + 被退出登录」排查
- 根因：`PracticeView.vue` 的 `onMounted` 第一行 `difficultyStore.load()`（不 await）→ `GET /api/exam/difficulty-config/list`。该接口是题目管理侧的只读配置接口，后端只对教师/管理员开放；学生拿到 403 后，`src/api/index.ts` 的「策略 A」把 403 当越权安全事件处理：弹错误 → `revokeToken()` 吊销当前 token → 清会话 → 跳 `/login?reason=forbidden`。所以一进页面就被踢。
- 关键点：这个请求是页面发出得最早的请求（先于章节、题目列表），现象与「一打开就 403 并退登录」完全吻合。学生端只有 `PracticeView`、`WrongBookView` 用到难度配置（后者只用来显示难度名）。
- 修复：
  - `src/api/index.ts`：`declare module 'axios'` 扩展 `AxiosRequestConfig.skipForbiddenLogout?: boolean`；响应拦截器的两处 403（业务 code=403 / HTTP 403）命中该标记时只 `Promise.reject`，**不弹全局错误、不吊销 token、不跳登录**。DEV 的 `console.warn('[403]', method, url)` 保留，便于定位接口。
  - `src/api/exam.ts`：`fetchDifficultyConfigs` 带上 `skipForbiddenLogout: true`。
  - `PracticeView.vue`：新增 `difficultyError`（`difficultyStore.error`），难度下拉在无选项时 `disabled`，并显示「难度筛选项暂不可用」（`.filter-note` 样式）。刷题本身不受影响。
- 待后端确认：建议把 `GET /api/exam/difficulty-config/list` 对学生开放（只读配置、无敏感信息），否则学生端只能按章节/题型筛选。
- 注意：修复前已被误踢的会话 token 已被吊销，需要重新登录一次。
- `vue-tsc --noEmit`（EXIT 0）+ `vite build` 通过。
